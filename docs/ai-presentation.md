# AI 파트 발표와 시연 준비

2026-11-13 작업 브랜치 기준이다. 실제 모델 실행과 프론트 통합이 끝나기 전에는 아래의 구현 설명을 실증 결과로 소개하지 않는다. 발표 전체 4분 중 AI 설명에 사용할 짧은 초안이며 팀 전체 발표 대본을 대신하지 않는다.

## AI 설명 초안

저희 AI 파트는 어르신의 관찰을 가족에게 전달하고, 텃밭 관리에 필요한 정보를 연결하는 역할입니다. 어르신이 말로 남기면 공개된 음성 인식 모델로 원문을 만들고, 언어 모델이 가족에게 보낼 문장과 관찰된 이상 징후를 정리하도록 구성했습니다. 결과는 어르신이 직접 확인하고 수정한 뒤 돌봄 기록과 가족 일기에 연결됩니다. 오늘 할 일에는 날씨와 작업 이력, 반복 간격, 하루 작업 시간 제한을 적용합니다. 성장 단계는 누적 기온 계산과 관리사의 실제 관찰을 함께 반영하도록 설계했습니다. 자체 모델 학습은 진행하지 않았고, 공개 모델의 로컬 추론과 서비스 로직을 연결했습니다.

실제 실행 검사가 끝나면 확인된 범위에 맞춰 "구성했습니다"를 "동작합니다"로 바꿀 수 있다. 예측 정확도, 농업 효과, 음성 인식 정확도와 응답 시간은 측정 전 수치를 넣지 않는다.

## 2분 시연 준비

| 순서 | 보여줄 내용 | 확인할 점 |
| --- | --- | --- |
| 시작 | 관리사 오늘 할 일 | 가상 시연 텃밭과 날씨임을 표시. 카드가 비어 있지 않은지 확인 |
| 관찰 기록 | 실제 녹음과 인식 원문, 정리문 | 사람이 원문과 발언이 맞는지 확인. 실패 결과를 성공으로 표시하지 않음 |
| 관리사 확인 | 정리문 수정과 확정, 사진 저장 | 사진 분석 미설치 상태를 AI 판정 완료라고 설명하지 않음 |
| 완료 | 작업 완료 후 가족 일기 새로 보기 | 같은 원문, 정리문, 사진이 가족에게 보이는지 확인 |
| 선택 | 비가 오는 날의 작업 또는 성장 확인 | 처리 시간이 남을 때만 진행. 방문 예약은 별도 영상이나 여유 시간에 배치 |

1. CPU의 실제 분석 시간을 먼저 측정한다. 전체 흐름이 2분에 들어가는지 확인한 경우에만 현장 녹음과 분석을 포함한다.
2. 분석이 길면 실제 녹음을 미리 처리해 저장한 뒤, "이 녹음의 분석 결과를 미리 준비했습니다"라고 밝히고 결과 확인, 확정, 완료와 가족 조회를 현장에서 보여준다. 가짜 원문을 넣거나 준비한 결과를 실시간 분석이라고 설명하지 않는다.
3. 시연할 미완료 작업과 메모를 남겨 둔다. 자동 smoke 검사의 --complete를 시연 직전에 실행해 마지막 작업을 소진하지 않는다. 이미 완료한 작업은 같은 날 다시 생성하지 않는다.
4. 모델과 DB를 미리 시작하고 마이크 권한, 사진 파일, 두 계정 로그인을 확인한다. 비밀번호 입력 화면은 녹화에서 제외한다. 실제 배포 링크가 준비되지 않았다면 로컬 실행을 배포 완료로 소개하지 않는다.
5. 영상은 실제 요청 흐름을 녹화하고, 재시도하거나 대체한 부분도 상태를 확인한다.

## 예상 질문과 답변

| 질문 | 답변 기준 |
| --- | --- |
| 직접 학습한 모델인가요? | 자체 학습은 하지 않았습니다. faster-whisper 기반 음성 인식과 Qwen2.5 3B 공개 모델의 로컬 추론을 연결하고, 권한 검증과 저장, 재시도, 작업 제약을 서비스 코드로 구현했습니다. |
| 단순 API 호출과 어떤 차이가 있나요? | 인식 결과를 바로 보내지 않고 초안으로 저장해 확인을 받습니다. 응답 유실 복구, 늦은 결과 덮어쓰기 방지, 완료 기록과 일기 연결을 처리합니다. 작업 생성은 모델 제안을 그대로 따르지 않고 검증된 작업 자료와 날씨, 이력, 시간 제약으로 제한합니다. |
| 작물이 실제로 다 자랐는지 AI가 알아내나요? | 성장 단계는 누적 기온 기반 추정과 관리사의 관찰 보정입니다. 실제 수확 가능 여부는 별도 현장 데이터 기준입니다. 현재 로컬 시연의 기온과 작물 기준은 가상 자료라 실제 농업 예측 성능을 입증하지 않습니다. |
| AI가 틀리거나 서버가 꺼지면 어떻게 되나요? | STT 실패 시 원문을 지어내지 않고 파일과 실패 상태를 보존합니다. 문장 정리만 실패하면 원문을 대체 정리문으로 두고 재시도할 수 있습니다. 최종 문장은 관리사가 확인하며, 완료 기록은 확인된 메모만 연결합니다. |
| 이상 징후는 병 진단인가요? | 관찰 원문에 있는 잎의 점, 노랗게 보이는 잎 등의 태그입니다. 병명이나 처방을 확정하는 기능은 아닙니다. |
| 비용과 인터넷 연결은 어떻게 되나요? | 이 구성은 유료 모델 API 키를 사용하지 않습니다. 이미지와 모델의 최초 다운로드에는 인터넷이 필요하고, 모델 추론은 같은 PC의 로컬 서버를 호출합니다. 공개 배포 서버의 운영 자원은 별도로 준비해야 합니다. |
| AI 사진 판별과 아바타는 동작하나요? | 사진 판별의 연결 코드는 있지만 기본 시연에는 비전 모델을 설치하지 않아 결과가 null입니다. 아바타는 생성 요청과 폴링 API가 있고, 서버에 이미지 모델 (`GEMINI_IMAGE_MODEL`)을 넣지 않으면 기본 SVG로 동작합니다. |
| 정확도와 속도는 얼마나 되나요? | 아직 실제 모델 측정 결과가 없습니다. 합성 한국어 문장 12개의 태그 평가와 지연 측정 도구를 준비했으며, STT와 요약 의미 보존은 실제 녹음으로 따로 확인해야 합니다. |
| 읽어주기도 자체 AI인가요? | 서버 TTS 공급자는 준비되지 않았습니다. 시연 콘솔은 브라우저 음성 읽어주기를 사용합니다. |

## 제출 전 승윤 담당 확인

1. 실제 서버 전체 빌드, 모델과 DB 부팅, 녹음 처리와 가족 일기 연결을 확인한다.
2. 측정 보고서가 있으면 합성 자료 수, 모델 이름, PC 환경, 대체 처리 여부와 함께 전달한다. 단위 테스트 수를 AI 정확도로 설명하지 않는다.
3. 팀 프론트에 원문과 정리문, 실패 상태, dry_ 일기 커서, API 접두어 없음, 브라우저 읽어주기 대체 기준을 공유한다. 상세 계약은 [ai-handoff.md](ai-handoff.md)에 있다.
4. 작업 브랜치를 GitHub에 올리고 원격 반영 여부를 확인한다. f16edaf까지 작업 브랜치 업로드를 확인했으며 이후 변경도 원격 반영 여부를 확인한다. main과 develop에는 병합하지 않는다.
5. 발표 PDF 담당자에게 실제 검증된 기능과 아직 준비되지 않은 항목을 구분해 전달한다. 숫자와 완료 여부는 실제 실행 뒤 확정한다.
