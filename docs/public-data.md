## 인증키와 공통 규칙

1. 두 API 모두 공공데이터포털(data.go.kr)의 같은 계정 인증키 하나를 쓴다. 포털 마이페이지의 "일반 인증키"다.
2. 인증키는 저장소에 올리지 않는다. 이 문서에도 적지 않는다. `.env`에만 둔다.
3. 환경변수 이름은 `PUBLIC_DATA_SERVICE_KEY`다 (`weather.kma.service-key`). 비워 두면 부팅은 되고 날씨 수집만 건너뛴다.
4. 포털이 보여주는 키는 이미 URL 인코딩된 값이다 (`%2B`, `%2F`, `%3D`가 들어 있다). 이 값을 쿼리 문자열에 그대로 붙이면 정상 동작한다 (확인함). 라이브러리가 한 번 더 인코딩하면 `%`가 `%25`로 바뀌어 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 난다. `KmaClient`는 키를 한 번만 인코딩한 문자열로 `URI.create(...)`를 만들어 넘긴다. 포털의 인코딩된 키와 디코딩된 키 어느 쪽을 넣어도 동작한다.
5. 호출은 `common/http`의 `externalRestClient`에서 파생한 클라이언트로 한다 ([development-guide.md](development-guide.md)).
6. HTTP 상태가 200이어도 본문의 `resultCode`가 실패일 수 있다. 반드시 `resultCode`를 본다. 기상청은 정상이 `"00"`, 모범음식점은 `"0"`이다 (확인함).

| 항목 | 기상청 단기예보 | 모범음식점 |
| --- | --- | --- |
| End Point | `https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0` | `https://apis.data.go.kr/1741000/excellent_restaurant_info` |
| 인증 파라미터 | `serviceKey` | `serviceKey` |
| 형식 지정 | `dataType=JSON` (기본 XML) | `returnType=json` |
| 계정 종류 | 개발계정 | 개발계정 |
| 활용기간 | 포털 마이페이지에서 확인 | 2026-11-11부터 2028-11-11까지 |
| 일일 트래픽 | 포털 마이페이지에서 확인 | 10,000건 |
| 이용허락범위 | 포털에서 확인 | 제한 없음 |

## 1. 기상청 단기예보 조회서비스

### 개요

1. 서비스 이름은 `VilageFcstInfoService_2.0`이다. REST GET, XML과 JSON을 지원한다.
2. 위경도가 아니라 5km 격자 좌표(`nx`, `ny`)로 조회한다. 남한만 제공한다.
3. 활용가이드 문서의 예시 주소는 `apihub.kma.go.kr`과 `authKey`로 적혀 있지만, 우리가 승인받은 것은 공공데이터포털 쪽이다. `apis.data.go.kr/1360000/...`과 `serviceKey`를 쓴다 (확인함).

| 오퍼레이션 | 이름 | 내용 | 우리 용도 |
| --- | --- | --- | --- |
| `getUltraSrtNcst` | 초단기실황 | 지금 관측값 (기온, 강수형태, 습도 등 8개) | 현재 날씨 |
| `getUltraSrtFcst` | 초단기예보 | 발표 시점부터 6시간 예보 | 쓰지 않아도 됨 |
| `getVilageFcst` | 단기예보 | 최대 5일 뒤까지 시간대별 예보 | 시간대별 예보, 강수확률, 적산온도 |
| `getFcstVersion` | 예보버전 | 자료가 수정됐는지 확인 | 쓰지 않아도 됨 |

### 요청

호출 주소는 `{End Point}/{오퍼레이션}`이다.

| 파라미터 | 필수 | 예시 | 설명 |
| --- | --- | --- | --- |
| `serviceKey` | O | | 인증키 |
| `pageNo` | O | `1` | 페이지 번호 |
| `numOfRows` | O | `1000` | 한 페이지 결과 수. 기본 10 |
| `dataType` | | `JSON` | 기본 XML |
| `base_date` | O | `20261111` | 발표일자 (YYYYMMDD) |
| `base_time` | O | `0500` | 발표시각 (HHmm). 아래 발표시각 규칙을 따른다 |
| `nx` | O | `64` | 격자 X |
| `ny` | O | `119` | 격자 Y |

`getFcstVersion`만 `base_date`, `base_time`, `nx`, `ny` 대신 `ftype`(ODAM 초단기실황, VSRT 초단기예보, SHRT 단기예보)과 `basedatetime`(YYYYMMDDHHmm)을 받는다.

요청 예시 (처인구청 격자의 초단기실황):

```
GET https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtNcst
    ?serviceKey={인증키}&pageNo=1&numOfRows=20&dataType=JSON
    &base_date=20261111&base_time=1100&nx=64&ny=119
```

### 응답

한 줄이 "시각 하나의 요소 하나"다. 같은 시각의 기온, 강수확률, 하늘상태가 서로 다른 줄로 온다. `category`로 묶어서 시각별 한 건으로 합쳐야 한다.

| 필드 | 설명 |
| --- | --- |
| `response.header.resultCode` | `"00"`이 정상 |
| `response.header.resultMsg` | `NORMAL_SERVICE` |
| `response.body.totalCount` | 전체 줄 수 |
| `response.body.items.item[]` | 결과 목록 |
| `baseDate`, `baseTime` | 발표일자, 발표시각 |
| `nx`, `ny` | 요청한 격자 (숫자) |
| `category` | 자료구분코드 (아래 표) |
| `obsrValue` | 실황 값. 초단기실황에만 있다 (문자열) |
| `fcstDate`, `fcstTime` | 예보 대상 날짜와 시각. 예보에만 있다 |
| `fcstValue` | 예보 값. 예보에만 있다 (문자열) |

### 코드값

| 코드 | 값 |
| --- | --- |
| `SKY` 하늘상태 | 1 맑음, 3 구름많음, 4 흐림 |
| `PTY` 강수형태 (단기예보) | 0 없음, 1 비, 2 비/눈, 3 눈, 4 소나기 |
| `PTY` 강수형태 (초단기) | 0 없음, 1 비, 2 비/눈, 3 눈, 4 소나기, 5 빗방울, 6 빗방울눈날림, 7 눈날림 |

`WeatherConditionResolver`가 이 코드를 `weather.condition`으로 바꾼다. 눈(3, 7)은 `COLD`, 나머지 강수는 `RAIN`, 강수가 없으면 기온과 하늘상태로 정한다.

값을 읽을 때 주의할 점:

1. 모든 값이 문자열로 온다. 숫자로 바꿔서 쓴다.
2. `PCP`와 `SNO`는 숫자가 아니라 문자열 범주다. 비가 없으면 `"강수없음"`, 눈이 없으면 `"적설없음"`이 온다. 있으면 `"1mm 미만"`, `"6.2mm"`, `"30.0~50.0mm"`, `"50.0mm 이상"`처럼 온다. 숫자로 파싱하면 실패하므로 우리는 저장하지 않는다.
3. +900 이상이나 -900 이하 값은 결측이다. 저장하지 않고 건너뛴다.
4. 연장 기간(02시부터 14시 발표의 글피, 17시부터 23시 발표의 그글피) 예보는 3시간 간격이고, 강수량, 적설, 풍속이 숫자 대신 정성 코드로 온다 (강수량 1 약한 비, 2 보통 비, 3 강한 비).

### 발표시각 규칙

`base_time`에 아직 발표되지 않은 시각을 넣으면 `NODATA_ERROR`(03)가 난다. 아래 "받을 수 있는 시각" 이후에 호출한다.

| 오퍼레이션 | 발표시각 (`base_time`) | 받을 수 있는 시각 |
| --- | --- | --- |
| 초단기실황 | 매시 정각 (`0000`부터 `2300`) | 매시 10분 이후. 이후 10분마다 갱신 |
| 초단기예보 | 매시 30분 (`0030`부터 `2330`) | 매시 45분 이후 |
| 단기예보 | `0200`, `0500`, `0800`, `1100`, `1400`, `1700`, `2000`, `2300` (하루 8회) | 각 발표시각의 10분 이후 |

`base_time` 고르는 법:

1. 초단기실황은 지금 분이 10분 미만이면 한 시간 전 정각, 아니면 이번 정각을 쓴다. 자정 직후에는 `base_date`도 전날로 바뀐다.
2. 단기예보는 지금 시각에서 10분을 뺀 뒤, 그보다 이르거나 같은 발표시각 중 가장 늦은 것을 쓴다. 02시 10분 전이면 전날 `2300`이다.

단기예보가 주는 범위:

| 발표시각 | 범위 |
| --- | --- |
| 02, 05, 08, 11, 14시 | 발표 시점부터 글피(3일 뒤)까지. 모레까지는 1시간 간격, 글피는 3시간 간격 |
| 17, 20, 23시 | 그글피(4일 뒤)까지. 마지막 날은 3시간 간격 |

일 최저기온(`TMN`)과 최고기온(`TMX`)은 발표시각에 따라 오늘 값이 빠진다. 오늘 최저는 02시 발표에만, 오늘 최고는 02시부터 11시 발표까지만 들어 있다. 우리는 `TMN`, `TMX`를 쓰지 않고 시간별 기온으로 `DailyWeather`를 직접 집계하므로 영향이 없다.

텃밭의 위경도에서 격자를 구하려면 아래 변환을 쓴다. 가이드의 C 예제(람베르트 정각원추도법)를 자바로 옮긴 것이고, 위 표의 값과 일치하는 것을 확인했다.

```java
public final class KmaGrid {
    private static final double RE = 6371.00877;   // 지구 반경 (km)
    private static final double GRID = 5.0;        // 격자 간격 (km)
    private static final double SLAT1 = 30.0;      // 표준위도 1
    private static final double SLAT2 = 60.0;      // 표준위도 2
    private static final double OLON = 126.0;      // 기준점 경도
    private static final double OLAT = 38.0;       // 기준점 위도
    private static final double XO = 43;           // 기준점 X (210km / 5km + 1)
    private static final double YO = 136;          // 기준점 Y (675km / 5km + 1)

    public static int[] toGrid(double latitude, double longitude) {
        double degrad = Math.PI / 180.0;
        double re = RE / GRID;
        double slat1 = SLAT1 * degrad;
        double slat2 = SLAT2 * degrad;
        double olon = OLON * degrad;
        double olat = OLAT * degrad;

        double sn = Math.log(Math.cos(slat1) / Math.cos(slat2))
                / Math.log(Math.tan(Math.PI * 0.25 + slat2 * 0.5) / Math.tan(Math.PI * 0.25 + slat1 * 0.5));
        double sf = Math.pow(Math.tan(Math.PI * 0.25 + slat1 * 0.5), sn) * Math.cos(slat1) / sn;
        double ro = re * sf / Math.pow(Math.tan(Math.PI * 0.25 + olat * 0.5), sn);

        double ra = re * sf / Math.pow(Math.tan(Math.PI * 0.25 + latitude * degrad * 0.5), sn);
        double theta = longitude * degrad - olon;
        if (theta > Math.PI) theta -= 2.0 * Math.PI;
        if (theta < -Math.PI) theta += 2.0 * Math.PI;
        theta *= sn;

        int nx = (int) Math.floor(ra * Math.sin(theta) + XO + 0.5);
        int ny = (int) Math.floor(ro - ra * Math.cos(theta) + YO + 0.5);
        return new int[]{nx, ny};
    }
}
```

## 2. 행정안전부 모범음식점정보 조회서비스

### 개요

1. 전국 모범음식점의 지정, 취소, 영업 상태를 준다. 매일 갱신되고 이틀 전 기준이다.
2. 오퍼레이션은 `/info` 하나다.
3. 좌표(위도, 경도)가 없다. 지도에 올리려면 주소를 좌표로 바꾸는 과정이 따로 필요하다.
4. 폐업했거나 지정이 취소된 업소도 함께 온다. 걸러서 써야 한다.

## 3. 전국농어촌체험휴양마을표준데이터

### 개요

1. 농어촌체험휴양마을로 지정된 마을의 이름, 체험 프로그램, 주소, 좌표를 준다.
2. 제공 기관별 파일 2개를 받았다. 한국농어촌공사 파일(농촌, 1,111건, 기준일 2026-09-22)과 한국어촌어항공단 파일(어촌, 150건, 기준일 2026-09-08)이다.
3. 용인시는 농어촌공사 파일에만 3곳이 있고 모두 처인구다. 어촌 파일에는 용인이 없다.
4. 건수가 적고 자주 바뀌지 않으므로 API로 연동하지 않고 시드 데이터로 넣는다.
5. 파일 인코딩은 UTF-8 (BOM 있음)이다. 모범음식점 CSV는 CP949라서 서로 다르다.

## 4. 주말농장 (참고)

1. 기획안의 "주말농장 현황 (공공데이터포털)"에 해당한다. `GET /farms`와 `POST /internal/farms/sync`가 쓴다 (이슈 #3, 팀원 담당).
2. 찾은 것은 [경기도 용인시 주말농장 (2015.12)](https://www.data.go.kr/data/15014158/fileData.do) 하나다. 2015년 12월 기준 9건짜리 1회성 파일이고 갱신되지 않는다.
3. 파일을 아직 받지 않아 열 구성은 확인하지 못했다. 받으면 이 절을 채운다.

## 남은 일

1. 로컬 `.env`와 배포 환경에 `PUBLIC_DATA_SERVICE_KEY` 넣기.
2. 농장마다 격자 값 정하기. 농장 도메인이 생기면 농장 위경도에서 위 변환식으로 격자를 구해 `WeatherFarmReader` 구현체를 등록한다.
3. 식당을 더 넣으려면 주소를 좌표로 바꾸는 방법 정하기 (`Outing.latitude`, `longitude`가 필수 값이다).
4. 주말농장 파일 확보와 열 구성 확인 (이슈 #3).
